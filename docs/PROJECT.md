目标：让用户在中文原生 Windows App 内管理独立项目目标、任务、知识来源、接手材料和证据。先建立本机文件控制层，顺序 AI 接力优先，不另造模型聊天平台。

本次可用 MVP 只管理 App 在本独立项目 data/local/Projects 内创建的项目。默认空白；示例位于 data/examples/Projects，显式切换，不混入本地搜索与导出。每个受管理项目有 repo/docs/CURRENT.md 指定的可编辑 Markdown 唯一事实源（PROJECT、STATE、tasks、knowledge），以及独立 docs、assets、data、runs、releases、archive。该沙盒是用户授权边界，不是系统沙箱或任意代理权限控制。

支持：项目创建与编辑；多任务创建与编辑；知识创建编辑、来源与适用范围、生命周期/验证分维；当前项目筛选；显式冲突并列；接手/交接预览、复制与唯一文件名 Markdown 导出；证据文件 SHA256 及来源锚点；原子保存、上一版本、版本冲突拒写、损坏提示与确认恢复；记录 ZIP 备份；重启读取持久文件；本项目登记文档与必要历史占用和运行时只读信息。

验收 done 需有效证据关联，仍不自动断言测试语义通过。知识 verified 是用户人工记录，界面注明，不是程序语义验证。批准要求编辑由用户显式确认；AI不得修改要求替自身错误开脱。

不支持：其他工作区导入/扫描，真实 AI 账户与自动代理，真实安装/清理/删除/迁移，系统配置，自动语义冲突判定，RAG、复杂并行、跨电脑与云同步、跨电脑备份迁移及覆盖原项目恢复。这些不作为本次完整单机 MVP 的承诺。

完整交付需外部桌面输入与物理缩放核验；当前因原生桌面工具缺失尚未验收，当前解锁状态未核验，不称生产版本。

本轮已授权核心补齐：每项目真实目录与薄AI规范模板；外部Markdown安全重读、差异核对及禁止旧内存覆盖；多文档完整快照与原子入口/显式恢复；任务登记文件SHA256与相关上下文。旧JSON仅显式升级输入/历史，不作新项目事实副本。未承诺所有27页能力。

v0.4仅新增获准的两个核心：所属repo的只读Git提交/分支/dirty/untracked受影响来源与接手包过期；完整项目安全内容备份、预览和本人确认后恢复到新独立副本。原v0.2.1/v0.3.0及既有App数据不自动迁移。安装/删除/系统配置/真实AI账户仍禁止。执行约定见GIT-AND-CONTENT.md。

v0.5获准的有界阶段：现有GitHub设计的只读检查、预览和审查计划导出；不新增远端写执行。批准需求未因测试失败而放宽。实际范围见PUBLICATION-PLAN.md；原项目导入、完整秘密审计、后台代理与真实安装/删除仍未承诺。
