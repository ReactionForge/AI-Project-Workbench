# 分支与版本规则

日常开发使用大写 DEV。main 为稳定线；初始 main 只有介绍与骨架，不代表原型已经生产验收。

每次大版本完成先提供精确 diff、测试结果、文档更新与发行候选说明，由项目用户决定是否将 DEV 合并到 main。普通 push 授权不包含合并授权。当前不执行 DEV → main 合并。

如需 PR，先建 draft；完成审阅后仍由用户决定转为正式和合并。不启用自动合并、自动发布或后台推送。遇到分歧保留双方提交，停止发布，不能 force push、重置或覆盖远端。

公开状态与本地状态分开：未提交、已提交未推送、远端同步、远端未知各如实标记。具体流程和未来 App UX 在 DEV 的 GITHUB-WORKFLOW.md 中。
