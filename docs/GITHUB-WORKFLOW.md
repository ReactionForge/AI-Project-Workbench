## 分支与授权
日常开发留在大写 DEV。main 是稳定线；初始 main 仅公开介绍、忽略规则和分支约定，不把现有原型当作稳定版。大版本先交付变更、验证和发行候选，由项目用户选择是否合并 DEV 到 main。公开 push 授权不包含合并、自动发布、账户设置、保护规则、持久 OAuth 或新增凭据授权。需要 PR 时只建 draft；本次不建 PR、不启用 Actions/自动合并。

## 状态必须分维度
|维度|状态|判定|
|---|---|---|
|工作区|未提交|有已修改、暂存或未跟踪的受审核文件；忽略文件不因此获得发布权限|
|工作区|已提交|指定清单对应本地 commit 已创建；其他脏文件仍单独列出|
|远端|已提交未推送|最近可信远端观察下，本地领先且远端不领先|
|远端|已同步|刚核对的目标分支 SHA 等于本地 SHA；不代表工作区没有新修改|
|远端|有分歧/落后|双方提交不同，需分析祖先及差异，不能自动覆盖|
|远端|未知|身份、权限、网络或观察时间不可靠；禁止显示推送成功|

现有 App 只读本项目 Git 事实；上述远端状态是后续设计，当前不伪造远端同步结果。网络失败保留最后成功观察的时间与 SHA，并明确“当前未知”。

## 发布前的精确计划
1. 用既有授权核实账号、owner/repository、可见性、目标分支、权限和预期远端 SHA；已有无关仓库不能接管。目标绑定保存在项目设置，不在通用运行代码写死任何用户身份、电脑或绝对路径。
2. 逐文件白名单加逐文件 diff；同时展示未暂存/已暂存/未跟踪/忽略项。提交内容以 index/blob 为准，不能只审工作副本，也不允许 git add 全目录碰碰运气。
3. 审查现有可达历史、待公开文件正文和提交作者信息。阻止真实密钥、凭据、个人路径/账户资料、用户原始输入、数据、日志、截图、Library 引用、下载 URL、工具与构建产物。本项目默认忽略全部，只开放已审查源码/合成夹具/必要文档；新增公开文件需更新白名单并复核。
4. 本项目策略：超过 5 MiB 的单文件暂不发布，先给出原因和替代方案；这是项目阈值，不冒称 GitHub 平台限制。不自动安装 LFS 或迁移历史。夹具中的 DEMO_ONLY 字符串须明确是合成占位，不能允许真实秘密冒充夹具。
5. 核对代码、需求与文档差异，跑相关静态检查/构建/领域测试，记录命令、实际输入源码版本、结果和未运行项。字段/hash 通过不等于业务、桌面或真实 AI 集成通过。
6. 创建经过审查的 commit 后再次核对目标与差异；变更文件或远端 SHA 后原预览失效，重新预览。记录本地 commit、文档修订、测试证据与待发布文件清单。

## 推送、未知结果与冲突
只允许目标项目 DEV 的正常 fast-forward 更新。普通 push 不隐含 main 合并。失败保留本地 commit，不清除、reset 或覆盖其他工作。
网络超时/断线时先查询目标分支 SHA 与 commit 是否已经存在，再判断成功或可重试；不重复创建仓库或盲目再写。仓库创建结果未知先核对同一 owner/name。
远端比预期前进则停止，给出双方 commit 与 diff，由用户决定重放/合并方案；不 force push、不重置远端，不自动运行清理/checkout 用户未授权状态。
推送后远端查询 SHA，要求与本地目标 commit 一致；再确认公开可见性、默认 main 和 DEV 存在。只在证据齐全时标记已同步。

## 版本与交付关联
每次候选记录：产品版本、批准需求修订、实际源 commit、源码清单/hash、测试输入版本/结果、文档修订、公开发行候选 SHA256。旧发行不回填新 commit；原型的内部检查不能补写为生产验收。
公开仓库源码不等于公开现有本地便携 ZIP。今后发行必须从干净的公开 commit 单独构建安全产物，排除用户资料/私人日志，完成目标平台验证后再由用户选择发布或合并。标签、GitHub Release、签名、provenance/供应链证明分别记录是否真实执行；未执行不显示徽章或认证。
CI、rulesets、签名、自动发行仅为待批准方案；本次不启用任何服务、secret 或证书。

## 后续 App UX（尚未实现）
入口“发布到 GitHub”：先选择当前项目的目标绑定，显示账号/仓库/可见性/大写 DEV/预期 SHA。未绑定、身份不符、未授权或无法观察远端时给出可理解的阻碍，保持本地工作可用。
分步界面：状态概览 → 精确文件与 diff 预览 → 检查结果/未运行项 → commit 预览 → 本次项目级 push 确认 → 远端核验/失败恢复。支持返回、取消；取消不启动网络写入。预览和确认不是一个自动后台动作。
每次授权绑定 project_id、账号、仓库、分支、清单/hash 与有效预览，不扩展到其他项目；改变目标、公开范围或访问权限需新确认。使用已有 OS/连接器授权，不在项目 Markdown、日志或配置存 token，不显示秘密。
成功页给出远端 URL、SHA、观察时间和剩余未提交内容。未知页提供“重新核对远端”而非假成功；冲突页展示差异，保留原 commit。主分支重大合并使用独立审阅与用户决策界面，draft PR 与正式合并不可合并成默认按钮。
