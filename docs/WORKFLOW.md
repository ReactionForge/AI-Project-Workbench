# 工作流
开始：加载AGENTS及当前任务包，核对已批准意图、实现差异、来源版本及受影响证据。不能以代码/测试现状推翻新要求；未知冲突只暂停受影响工作。小任务针对性加载，高风险升级。

知识：来源角色为已批准意图/观察实现/待批准方案/复用经验。生命周期active/superseded/retired与验证verified/needs_verification/unknown独立。最后验证时间不是生命周期。手动记录来源和适用范围；待批准不得当要求。被替代历史默认排除。

接手：先预览，核对project_id、任务目标、范围、负责人、来源指纹、当前证据、已做未做和下一步。仅当前项目。包是派生材料，不作为唯一事实。当前不自动执行代理。旧AI停写，新AI顺序接手；复杂并行后置。

实现：只在本项目写入。源码、正式测试与现行文档同repo。缓存和临时在runs；不得改USERPROFILE、AppData、全局PATH或注册表。构建必须经build.ps1。

验收：检查需求/实现差异，核对测试所测版本与证据指纹；指纹变化只标重核，不能自动改变要求。程序夹具、内部WPF渲染、外部桌面输入、真实AI集成分别记录。未运行不标通过。

收尾：保留源码、正式测试与必要失败证据；固定release清单和哈希。清理仅设计预览，不执行删除。交接增量更新当前任务卡，不另外复制现行状态。原始资料保存在外层docs，现行真相唯一repo/docs。Obsidian可直接阅读同一份Markdown，本次不安装客户端或插件。

公开 GitHub 工作流以 GITHUB-WORKFLOW.md 为准；DEV 开发、main 重大合并由用户决定。
